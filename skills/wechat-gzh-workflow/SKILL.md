# 公众号全流程工作流（一个人从选题到草稿箱）

把「做一篇公众号」拆成 6 个关卡，每关只做一件事，产出物落到固定目录，下一关卡直接复用。目标是让一个没有团队的人，也能稳定产出可发布的稿子。

## When to Use

- 你要独立完成一篇公众号文章，从选题一直做到微信草稿箱。
- 你已经装了 Hermess Agent Desktop，并能接入至少一个文本模型和一个出图后端。
- 不适用于：纯转发、纯视频脚本、多账号矩阵批量洗稿（本工作流主打单篇质量，不做洗稿）。

## 前置约定

1. 建一个工作区根目录，全程所有文件只放这里，按下面分类，不散落临时目录：

```
工作区根/
├── 01_选题卡/
├── 02_文章/（按系列分子目录）
├── 03_图片/（正文配图、封面、品牌资产分开）
├── 04_排版HTML/
├── 05_发布记录/
└── 06_数据分析/
```

2. 文件统一命名：`YYYY-MM-DD-标题关键词`，同一篇的选题卡、正文、标题候选、短内容用同一日期前缀，方便回查。
3. 配图省钱第一原则：按系列出图而不是按文章出图，同一系列复用一套图；出图前先找旧图；默认用最低画质档，能用就不升档。
4. 真实截图优先于 AI 生图：工具教程类的界面、步骤、报错一律用真实截图，既省钱又更可信。

## 六个关卡

### 关卡 1：选题（产出选题卡）
- 先定内容类型，再定选题。工具型常青内容优先（教程、清单、实测、省钱），纯观点热点不做主力，因为热点带来的是一次性路人，涨粉转化差。
- AI 闸门（一票否决）：选题必须是 AI 驱动的工具，或 AI 工作流里的一环；非 AI 通用工具要挂到具体 AI 场景，不能独立成篇。
- 联网检索做选题卡，写清：目标读者和搜索词、核心痛点、内容骨架、参考资料链接、本机实测还是 README 推荐模式。
- 选题卡存入 `01_选题卡/`。

### 关卡 2：写正文（产出 Markdown）
- 先结论后原因，开头三行内出现具体场景或具体数字，禁止“随着XX飞速发展”式大词开场。
- 短段落，口语第一人称；干货数字、版本号、价格额度一个不删。
- 两种诚实模式：本机实测模式写“我跑过”，截图和数字写死；README 推荐模式必须分清“我验证过的”和“官方记载没跑到的”，绝不编造成果截图和准确率。
- 正文存入 `02_文章/系列名/`。

### 关卡 3：去 AI 味
- 用去AI味技能过一遍，保留作者原本的语气和真实信息，只改机器腔。
- 检查并删掉：空洞排比、正确的废话、过度对仗的三段式、没有信息量的升华。
- 敢下不和稀泥的结论，敢写缺点和翻车，全夸等于广告，没人信。

### 关卡 4：配图与封面
- 正文图按 16:9、封面按 21:9 出；先翻 `03_图片/` 找可复用的旧图。
- 工具步骤用真实截图，需要 AI 配图时走统一出图后端，最低画质档。
- 在正文需要配图的位置放图片占位符，保持顺序，排版时按顺序替换。

### 关卡 5：排版（产出 HTML）
- 选一套固定排版风格，全系列保持一致，建立辨识度。
- 段落尽量短，平均段长控制在 40 字左右，用空行而不是花哨分隔线切节奏。
- 把图片占位符按出现顺序替换成本地图路径，产出可直接给微信用的 HTML，存入 `04_排版HTML/`。

### 关卡 6：上传草稿箱与归档
- 用发布技能把封面、正文图片、HTML 上传到微信草稿箱，自动处理图片 URL 替换。
- 上传成功后，在 `05_发布记录/` 记一条：日期、标题、封面、用到的图片、发布账号。
- 清理临时依赖和虚拟环境；正式发布后再回填一次数据到 `06_数据分析/`，用来反哺下一轮选题。

## 标题与短内容

- 标题走“具体数字 + 痛点 + 收益 + 判断词”的口语结构，工具名必须进标题（小号靠搜索，不能学头部号弱化关键词）。
- 每篇长文配一条约 300 字短内容：结论前置 + 一个钩子 + 跳转长文，双发吃短内容流量。

## 人工把关清单（不可全自动的环节）

- 选题判断和价值观：机器给候选，人拍板。
- 终审：事实、数字、合规、署名协议，发布前人必须过一遍。
- 涉及删除、外发、花钱的动作，一律保留人工审批，不交给自动任务。

## 效果对照（作者本人数据，仅作说明，非通用承诺）

- 热点文（Kimi/GLM/可灵类）阅读几百但涨粉接近 0；一篇具体工具实操教程带来的新粉占当月新增的大多数。
- 结论：对小号来说，“以后用得上”的可收藏实操内容，比追热点更能涨粉。你的实际数据请自己记录验证，不要直接套用这个数字。
